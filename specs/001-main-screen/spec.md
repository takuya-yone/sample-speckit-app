# Feature Specification: メイン画面

**Feature Branch**: `002-main-screen`
**Created**: 2026-04-23
**Status**: Draft
**Input**: User description: "メイン画面を作成"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 商品一覧の閲覧 (Priority: P1)

初めてサイトを訪れたユーザーが、トップページで取り扱い中の
お米の一覧を視覚的に確認し、興味のある商品を見つけることが
できる。商品カードには商品画像、品種名、産地、価格、簡単な
説明が表示される。

**Why this priority**: メイン画面の最も基本的な役割は商品を
見せることであり、これがなければサイトとして成立しない。

**Independent Test**: トップページにアクセスし、商品カードが
一覧表示されていること、各カードに必要情報が揃っていること
を目視で確認できる。

**Acceptance Scenarios**:

1. **Given** ユーザーがサイトにアクセスした, **When** メイン画面が
   表示される, **Then** お米の商品カードが一覧で表示される
2. **Given** 商品一覧が表示されている, **When** ユーザーが
   個々のカードを見る, **Then** 商品画像・品種名・産地・
   価格・説明が表示されている
3. **Given** 商品が複数ある, **When** 画面を下にスクロール
   する, **Then** 追加の商品が表示される

---

### User Story 2 - ヒーローセクションの表示 (Priority: P2)

ユーザーがメイン画面にアクセスした際、画面上部にブランドの
世界観を伝える視覚的に魅力的なヒーローセクションが表示され、
サイトの目的（お米の販売）が一目で伝わる。

**Why this priority**: 第一印象でサイトの信頼性と目的を伝える
ことはコンバージョンに直結するが、商品一覧が先に必要。

**Independent Test**: メイン画面にアクセスし、ヒーロー画像
とキャッチコピーが目立つ位置に表示されていること、主要な
アクションへの導線があることを確認できる。

**Acceptance Scenarios**:

1. **Given** ユーザーがメイン画面を開いた, **When** ページが
   読み込まれる, **Then** ヒーロー画像・キャッチコピーが
   画面上部に表示される
2. **Given** ヒーローセクションが表示されている, **When**
   ユーザーがアクションボタンを押す, **Then** 商品一覧
   セクションへスムーズにスクロールする

---

### User Story 3 - レスポンシブ対応 (Priority: P1)

スマートフォン・タブレット・デスクトップのどのデバイスから
アクセスしても、メイン画面が適切なレイアウトで表示され、
快適に閲覧できる。

**Why this priority**: ユーザーの多くがモバイルからアクセス
するため、レスポンシブ対応は商品一覧と同等に重要。

**Independent Test**: 各デバイスサイズ（375px, 768px, 1280px）
でメイン画面を表示し、レイアウトが崩れず操作可能であること
を確認できる。

**Acceptance Scenarios**:

1. **Given** スマートフォン（幅375px）でアクセスした,
   **When** メイン画面が表示される, **Then** 商品カードが
   1列で縦に並び、すべての情報が読める
2. **Given** タブレット（幅768px）でアクセスした, **When**
   メイン画面が表示される, **Then** 商品カードが2列で並ぶ
3. **Given** デスクトップ（幅1280px）でアクセスした, **When**
   メイン画面が表示される, **Then** 商品カードが3列以上で並ぶ

---

### Edge Cases

- 商品データが0件の場合、「現在お取り扱い中の商品はありません」
  と表示する
- 商品画像が読み込めない場合、代替画像（プレースホルダー）を
  表示する
- 非常に長い商品名や説明文がある場合、適切に省略表示する

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: メイン画面はヒーローセクション、商品一覧セクション、
  フッターで構成される MUST
- **FR-002**: 商品カードには商品画像、品種名、産地、価格（税込）、
  短い説明文を表示する MUST
- **FR-003**: 商品一覧はグリッドレイアウトで表示し、デバイス幅に
  応じてカラム数を変更する MUST
- **FR-004**: ヒーローセクションにはメインビジュアルと
  キャッチコピーを表示する MUST
- **FR-005**: ヒーローセクションにページ内スクロールを誘導する
  アクションボタンを設置する MUST
- **FR-006**: メイン画面のナビゲーションバーにはサイト名を
  表示する MUST
- **FR-007**: 商品データが0件の場合、空状態メッセージを
  表示する MUST
- **FR-008**: 商品画像が読み込めない場合、プレースホルダー
  画像を表示する MUST

### Key Entities

- **商品 (Product)**: 品種名、産地、価格、説明文、商品画像。
  メイン画面の中心的な表示要素
- **商品カテゴリ**: 将来的な分類用。メイン画面 v1 では使用しない

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーがメイン画面にアクセスしてから商品一覧が
  表示されるまで3秒以内
- **SC-002**: モバイル・タブレット・デスクトップの3デバイスで
  レイアウト崩れがゼロ
- **SC-003**: 90%以上のユーザーがスクロールせずにサイトの
  目的（米販売）を理解できる
- **SC-004**: すべてのインタラクティブ要素が目視で識別でき、
  タップ/クリックで正しく動作する

## Assumptions

- 商品データは初期段階ではハードコードされたサンプルデータ
  を使用する（将来的にバックエンドAPI連携を想定）
- ユーザー認証やカート機能はメイン画面のスコープ外
- 日本語のみをサポートする（多言語対応はスコープ外）
- お米の品種は日本の一般的な品種（コシヒカリ、あきたこまち等）
  を想定
- フッターには最低限のサイト情報（コピーライト等）を表示する
