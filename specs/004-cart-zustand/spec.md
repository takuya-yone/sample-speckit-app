# Feature Specification: カート機能の実装

**Feature Branch**: `004-cart-zustand`
**Created**: 2026-04-24
**Status**: Draft
**Input**: User description: "カート機能を実装、状態管理はzustandを利用"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 商品をカートに追加 (Priority: P1)

ユーザーが商品一覧ページで気になるお米を見つけた際、
「カートに追加」ボタンを押すことで、その商品をカートに
入れることができる。カートに追加された商品数がヘッダーの
カートアイコンにバッジとして表示され、ユーザーは現在の
カート内容を一目で把握できる。

**Why this priority**: カートに商品を追加できることが
ショッピング体験の最も基本的な機能であり、これがなければ
他のカート関連機能が成立しない。

**Independent Test**: 商品一覧で任意の商品の「カートに追加」
ボタンを押し、ヘッダーのカートバッジの数が増えることを
確認する。同じ商品を複数回追加した場合、数量が増加する
ことを確認する。

**Acceptance Scenarios**:

1. **Given** 商品一覧が表示されている, **When** 商品カードの
   「カートに追加」ボタンを押す, **Then** その商品がカートに
   1個追加される
2. **Given** 商品がカートに追加された, **When** ヘッダーを
   確認する, **Then** カートアイコンに合計商品数がバッジで
   表示される
3. **Given** 既にカートに入っている商品, **When** 同じ商品の
   「カートに追加」ボタンを再度押す, **Then** その商品の
   数量が1増加する
4. **Given** カートが空の状態, **When** ヘッダーを確認する,
   **Then** カートバッジは表示されない（または0と表示）

---

### User Story 2 - カート内容の確認と数量変更 (Priority: P1)

ユーザーがカートアイコンをクリックすると、カートの詳細が
表示される。カート内では各商品の名前、単価、数量、小計が
表示され、数量の増減や商品の削除ができる。カートの合計
金額がリアルタイムで更新される。

**Why this priority**: カートの内容を確認・編集できなければ
購入意思の確認ができず、ユーザー体験として不完全である。

**Independent Test**: カートに複数の商品を追加後、カートを
開き、数量の変更と商品の削除を行い、合計金額が正しく
再計算されることを確認する。

**Acceptance Scenarios**:

1. **Given** カートに商品がある, **When** カートアイコンを
   クリックする, **Then** カートの詳細（商品名、単価、数量、
   小計、合計金額）が表示される
2. **Given** カートの詳細が表示されている, **When** 商品の
   「+」ボタンを押す, **Then** その商品の数量が1増加し、
   小計と合計が更新される
3. **Given** カートの詳細が表示されている, **When** 商品の
   「-」ボタンを押す, **Then** その商品の数量が1減少し、
   小計と合計が更新される
4. **Given** 数量が1の商品, **When** 「-」ボタンを押す,
   **Then** その商品がカートから削除される
5. **Given** カートの詳細が表示されている, **When** 商品の
   「削除」ボタンを押す, **Then** その商品がカートから
   完全に削除される
6. **Given** カート内のすべての商品を削除した, **When**
   カート画面を確認する, **Then** 「カートは空です」という
   メッセージが表示される

---

### User Story 3 - カート状態の永続化 (Priority: P2)

ユーザーがブラウザを閉じて再度サイトを訪問した際、
前回のカート内容が復元される。これにより、ユーザーは
買い物の途中で離脱しても、続きから再開できる。

**Why this priority**: ユーザーの利便性を大幅に向上させる
機能だが、カートの基本機能（追加・確認・編集）がなければ
永続化する対象がないため、P2とする。

**Independent Test**: カートに商品を追加した後、ブラウザの
タブを閉じて再度サイトを開き、カートの内容が復元されて
いることを確認する。

**Acceptance Scenarios**:

1. **Given** カートに商品がある状態でページをリロードする,
   **When** ページが再表示される, **Then** カートの内容が
   維持されている
2. **Given** カートに商品がある状態でブラウザタブを閉じる,
   **When** 再度サイトにアクセスする, **Then** 前回の
   カート内容が復元される
3. **Given** カートの商品数量を変更した後にリロードする,
   **When** ページが再表示される, **Then** 変更後の数量が
   維持されている

---

### Edge Cases

- カートに追加できる1商品あたりの最大数量は99個とする
  （99個の状態で追加を試みた場合、数量は増加しない）
- 商品データが変更された場合（価格変更など）、カート内の
  価格は最新の商品データに基づいて表示する
- カートが空の状態でカート画面を開いた場合、適切な空状態
  メッセージと商品一覧への導線を表示する

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 商品一覧の各商品カードに「カートに追加」
  ボタンを表示する MUST
- **FR-002**: カートに追加された商品の数量を管理する
  （同一商品の重複追加は数量増加として処理） MUST
- **FR-003**: ヘッダーにカートアイコンと商品合計数の
  バッジを表示する MUST
- **FR-004**: カートの詳細画面で商品名、単価、数量、小計、
  合計金額を表示する MUST
- **FR-005**: カート内の商品の数量を増減できる MUST
- **FR-006**: カートから商品を削除できる MUST
- **FR-007**: カートの合計金額をリアルタイムで計算・
  表示する MUST
- **FR-008**: カートの状態をブラウザのローカルストレージに
  保存し、再訪問時に復元する SHOULD
- **FR-009**: 1商品あたりの最大数量を99個に制限する SHOULD
- **FR-010**: カートが空の場合、空状態メッセージと商品
  一覧への導線を表示する MUST

### Key Entities

- **カートアイテム (Cart Item)**: 商品への参照、数量。
  商品一覧の商品データと紐づく。カート内で一意に識別される。
- **カート (Cart)**: カートアイテムの集合。合計金額、
  合計商品数を算出できる。ブラウザごとに1つ存在する。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーが商品をカートに追加する操作が
  1秒以内に完了し、画面に反映される
- **SC-002**: カート内の数量変更・削除操作が即座に
  合計金額に反映される（体感遅延なし）
- **SC-003**: ページリロード後もカート内容が100%
  復元される
- **SC-004**: カートの全操作（追加、数量変更、削除、
  表示）がエラーなく動作する
- **SC-005**: カートが空の状態から商品を追加し、数量を
  変更し、一部を削除するまでの一連の操作が直感的に
  完了できる

## Assumptions

- 本機能はフロントエンドのみで完結する（バックエンドAPI、
  データベースは不要）
- 決済・注文確定機能はスコープ外（将来の機能として想定）
- ユーザー認証は不要（ゲストユーザーとして動作）
- カートの永続化にはブラウザのローカルストレージを使用する
- 商品データは既存のハードコードされたデータ（6品種）を
  使用する
- カートの表示形式はドロワー（サイドパネル）またはモーダル
  とする
- 税込み価格は既に商品データに含まれているため、追加の
  税計算は不要
- レスポンシブデザインは既存のアプリケーションの方針に従う
